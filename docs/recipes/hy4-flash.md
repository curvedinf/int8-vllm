# Serve HY4-Flash on MI100

Run Tencent’s HY4-Flash as a chat API with text, image and video input. Use four 32 GiB MI100s on one Linux host and allow about 113 GiB of SSD space for the [INT4 target and its n-gram tables](https://huggingface.co/voodooquant/Hy4-flash-NeUQI-INT4-W4A8-GS128) and the [INT8 DFly2 draft](https://huggingface.co/voodooquant/Hy4-flash-DFly2-PTQR-INT8-W8A8-GS128). The optional startup weight cache takes another 82 GiB.

## Docker Compose

From the root of your [MI100 checkout](mi100-install.md#docker), start the server. Use `MI100_XGMI=off` for four cards connected over PCIe. The launcher downloads both checkpoints on first use.

```bash
MI100_CARDS=4 MI100_XGMI=on \
  docker compose -f docker/mi100/compose.hy4.yaml up --build --wait
```

## Send a chat

When Compose reports the service healthy, it is ready at `http://127.0.0.1:8020/v1`. Use `hy4-flash` as the model ID. This example reads the key generated by the launcher. If you supplied a key, use that value for `api_key`.

```bash
api_key="$(docker compose -f docker/mi100/compose.hy4.yaml exec -T serve cat /cache/mi100/api.key)"
curl -fsS http://127.0.0.1:8020/v1/chat/completions \
  -H "Authorization: Bearer $api_key" \
  -H 'Content-Type: application/json' \
  -d '{"model":"hy4-flash","messages":[{"role":"user","content":"Suggest a one-pot dinner."}],"max_tokens":256}'
```

Stop the container with `docker compose -f docker/mi100/compose.hy4.yaml down`. The named volume keeps the downloads for the next start.

## Native serving

After [building the native MI100 environment](mi100-install.md#native), install FlyDSL in the serving venv and start the same recipe.

```bash
.venv/bin/python -m pip install --dry-run 'flydsl==0.5.0'
.venv/bin/python -m pip install 'flydsl==0.5.0'
export MI100_RECIPE=hy4 MI100_CARDS=4 MI100_XGMI=on
scripts/mi100-serve.sh start
```

Use the [native API key](mi100-install.md#api-access) for the chat request above. From the same shell, run `scripts/mi100-serve.sh status` to see the service state or `scripts/mi100-serve.sh stop` to shut it down.

## Memory and context

The launcher allows eight concurrent requests and up to 262,144 input and output tokens combined per request. Active requests share a GPU-only KV cache. `HY4_HOST_RAM_RESERVE_GIB` defaults to `8` and tells the launcher how much system RAM to keep free when loading the n-gram tables.

### N-gram storage

The four packed tables live in the target checkpoint’s `engram/` directory. For automatic Docker downloads, put the cache volume on SSD. To reuse local checkpoints, mount their parent with `MODELS_DIR` and set `MODEL_DIR` and `DRAFT_MODEL_DIR` to the corresponding paths under `/models`. Set `ENGRAM_DIR` if the tables are elsewhere. [Docker storage and overrides](mi100-install.md#overrides)

| `ENGRAM_MODE` | Where to put the tables |
| --- | --- |
| `bcache` (default) | Keep the files on an SSD or an SSD-backed filesystem. The launcher can warm a Linux bcache device on startup. |
| `direct` | Use a filesystem and storage device that support physical GPU-direct reads through AMD Infinity Storage. |
| `ram` | Allow another 33.57 GiB of available system RAM to pin the tables, in addition to the host RAM reserve. |

To skip the optional rank-local weight cache, set `ADDITIONAL_CONFIG='{"hy4_rank_cache":false}'` in `docker/mi100/recipe.env`. For a native launch, export the same setting in your shell.
